# 立之雲端庫・本機版

這是立之雲端庫的本機版與 GitHub Pages 網站。影音目錄與音檔透過 GitHub 發布；知識庫筆記、文件、收藏、收聽進度仍儲存在各裝置的瀏覽器，不會自動跨裝置同步。版本 18 的共用對話獨立儲存在 Supabase，會自動跨裝置同步。

## 啟動

雙擊 `啟動立之雲端庫.cmd`，瀏覽器會開啟 `http://127.0.0.1:4180`。

## 已完成

- 知識庫：資料夾、筆記、標籤、文件與圖片上傳、搜尋、回收桶
- 影音庫：多檔音訊／影片上傳、播放、播放速度、收藏、搜尋
- Podcast：已生成的 Podcast 直接集中在影音庫播放與管理
- 即時對話：所有訪客共用同一份雲端紀錄，不用登入、配對或保持另一台裝置在線。打字停頓或貼上後自動傳送。
- 立之讀書室：直接嵌入雲端庫介面，不另開新分頁
- A4 文件編輯器：直向／橫向 A4、固定位置文字框、建立後仍可調整列欄與拖曳內部分隔線的可移動表格、獨立圖片與儲存格內圖片、模板、Word DOCX／PDF 匯出，直接嵌入雲端庫
- 備份：匯出／匯入筆記、分類與 Podcast 設定

## 資料位置

本機文件與筆記存放在瀏覽器 IndexedDB；收藏與播放進度儲存在 localStorage。請固定使用同一個瀏覽器開啟，並定期在「本機設定」匯出資料目錄。

大檔影音仍保存在瀏覽器資料庫中；匯出的 JSON 備份不包含影音檔本體。

共用對話是公開資料：所有訪客可讀取及新增，裝置名稱不是身分驗證。只公開新的 `lizhi_cloud_messages`，原有教材、帳戶和私人表的權限不變。舊版配對紀錄、草稿與待傳資料保留在原 localStorage key，不自動匯入公開空間。

## 工作畫面與傳送可靠性

- 開關選單、搜尋與切換區域會保留播放器、讀書室 iframe、A4 iframe。只有重新整理頁面或明確點選重新載入才會重建這些畫面。
- 音訊不會自動開始播放；按播放後恢復此裝置上次進度。支援收藏、已聽完、下一集與自動連播，切換區域可用底部控制列暫停。
- 共用對話每 3 秒檢查新紀錄；頁面背景或離開對話區時降至 15 秒，回到頁面立即同步。失敗逐步延後重試，單次請求最多 12 秒，斷網不假裝成功。
- 傳送前保存待傳佇列，伺服器確認寫入後才標「已存到雲端」（不代表有人已讀）。重送相同 ID 不會重複，伺服器統一時間排序。
- 最多 100 段待傳訊息；畫面只顯示雲端最近 80 筆。每段最多 10,000 字，每裝置每分鐘 30 段、全站每分鐘 300 段；共用表最多 10,000 段，滿了保留本機待傳並提示管理者處理，不自動刪除歷史。
- 無登入無法可靠識別使用者、阻止冒名或完全防止濫用。全站限量只作基本保護；若需私人用途，必須重新加上認證與隔離。
- 中文選字期間暫停自動送出，輸入草稿獨立保存在此裝置。
- 「上傳狀態」讀取 upload-status.json，顯示回報時間、最近資產更新與待傳數量。超過 26 小時會標示過期，並非遠端電腦的即時監控。

## 每次上傳後的回報

在專案目錄執行 `node scripts/report-upload-status.mjs`，核對目錄、雲端資產及 imports 待傳檔案。需要已登入的 GitHub CLI。
上傳工作失敗時執行 `node scripts/report-upload-status.mjs --error "上傳工作失敗"`。將產生的 upload-status.json 隨本次目錄變更提交、推送；無新音檔也應發布本次回報。

## 驗證

啟動 server.mjs 後，用已安裝 Playwright 的環境執行 scripts/verify-workspace.cjs。TEST_BASE 可指定測試網址，預設為 http://127.0.0.1:4186；PLAYWRIGHT_MODULE 可指定本機套件路徑。測試使用隔離瀏覽器資料與替代音訊，不修改使用者資料。
scripts/verify-cloud-chat.cjs 使用隔離瀏覽器與模擬雲端，測試無配對同步、晚加入、斷線佇列、重試去重、中文輸入、草稿與畫面穩定。
scripts/verify-chat-live.cjs 使用真實雲端，會新增一筆明確標記為功能驗證的公開訊息，驗證另一裝置收到、發送端關閉後仍能讀取，以及重送去重。

## 雲端資料庫維護

- GitHub Pages 只提供前端，`cloud-chat.js` 以公開 publishable key 存取指定 Supabase 專案；沒有管理金鑰或 OpenAI API 費用設定。
- `database/001_public_chat.sql` 是一次性建立腳本（已套用於 dtgtkrlzufylyvcbgggw），不要在同一資料庫重複執行。新資料表開啟 RLS，訪客只能 SELECT；INSERT 僅能呼叫受限的 `lizhi_send_message` 函式，訪客不能直接 INSERT/UPDATE/DELETE。
- SQL 使用交易、固定 search_path、鎖定後檢查限量及冪等 ID。只操作此新增共用表，不變更讀書室的私人資料權限。
- 需要清理或匯出全部歷史時，由管理員於 Supabase 處理；不要把 service-role 金鑰放進靜態網站。
- 舊 `chat-delivery.js` 為版本 17 的封存原始碼，不再由網站載入。
