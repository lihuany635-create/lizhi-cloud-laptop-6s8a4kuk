# 立之雲端庫・本機版

這是立之雲端庫的本機版與 GitHub Pages 網站。影音目錄與音檔透過 GitHub 發布；知識庫筆記、文件、收藏、收聽進度與即時傳字紀錄仍儲存在各裝置的瀏覽器，不會自動跨裝置同步。

## 啟動

雙擊 `啟動立之雲端庫.cmd`，瀏覽器會開啟 `http://127.0.0.1:4180`。

## 已完成

- 知識庫：資料夾、筆記、標籤、文件與圖片上傳、搜尋、回收桶
- 影音庫：多檔音訊／影片上傳、播放、播放速度、收藏、搜尋
- Podcast：已生成的 Podcast 直接集中在影音庫播放與管理
- 即時對話：透過私人邀請網址，在手機與電腦之間點對點傳字；本機版複製的邀請會自動使用 GitHub Pages 雲端網址，貼上或打字後會自動傳送
- 立之讀書室：直接嵌入雲端庫介面，不另開新分頁
- A4 文件編輯器：直向／橫向 A4、固定位置文字框、建立後仍可調整列欄與拖曳內部分隔線的可移動表格、獨立圖片與儲存格內圖片、模板、Word DOCX／PDF 匯出，直接嵌入雲端庫
- 備份：匯出／匯入筆記、分類與 Podcast 設定

## 資料位置

本機文件與筆記存放在瀏覽器 IndexedDB；收藏與播放進度儲存在 localStorage。請固定使用同一個瀏覽器開啟，並定期在「本機設定」匯出資料目錄。

大檔影音仍保存在瀏覽器資料庫中；匯出的 JSON 備份不包含影音檔本體。

即時對話使用 WebRTC 加密的點對點連線，兩台裝置需同時在線；對話紀錄只儲存在各裝置的瀏覽器。

## 工作畫面與傳送可靠性

- 開關選單、搜尋與切換區域會保留播放器、讀書室 iframe、A4 iframe。只有重新整理頁面或明確點選重新載入才會重建這些畫面。
- 音訊不會自動開始播放；按播放後恢復此裝置上次進度。支援收藏、已聽完、下一集與自動連播，切換區域可用底部控制列暫停。
- 即時傳字先將訊息保存到待傳佇列，再傳給已連線裝置，收到新版接收端確認才標示送達（代表至少一台對方裝置收到，並非全部裝置）。每四秒重試未確認訊息，接收端會去重。最多 100 段待傳訊息，歷史保留最近 80 段，另保留最近 2,000 個接收 ID。
- 中文選字期間不自動送出。輸入草稿獨立保存。雙方需更新網站才能提供新版接收確認；各網路的 WebRTC 可用性仍取決於網路環境。
- 初次配對：在手機開啟筆電的「複製連線網址」，或展開「配對／確認兩台是否同一房間」貼上完整配對碼。分別開首頁會建立不同房間，必須先配對一次。版本 17 會交換同一房間最近 80 筆歷史，補上舊版留下的紀錄；原房間資料保留在原房間。
- 「上傳狀態」讀取 upload-status.json，顯示回報時間、最近資產更新與待傳數量。超過 26 小時會標示過期，並非遠端電腦的即時監控。

## 每次上傳後的回報

在專案目錄執行 `node scripts/report-upload-status.mjs`，核對目錄、雲端資產及 imports 待傳檔案。需要已登入的 GitHub CLI。
上傳工作失敗時執行 `node scripts/report-upload-status.mjs --error "上傳工作失敗"`。將產生的 upload-status.json 隨本次目錄變更提交、推送；無新音檔也應發布本次回報。

## 驗證

啟動 server.mjs 後，用已安裝 Playwright 的環境執行 scripts/verify-workspace.cjs。TEST_BASE 可指定測試網址，預設為 http://127.0.0.1:4186；PLAYWRIGHT_MODULE 可指定本機套件路徑。測試使用隔離瀏覽器資料與替代音訊，不修改使用者資料。
scripts/verify-chat-live.cjs 以兩個隔離瀏覽器實際測試 PeerJS 傳送、接收確認與重新連線。
